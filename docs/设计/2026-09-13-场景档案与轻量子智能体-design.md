# 场景档案与轻量子智能体 设计

**Status:** draft

- **日期**：2026-09-13
- **范围裁定（用户）**：场景 = 记忆 + MCP + Skills + **子智能体绑定**，一个版本交付；钩子不做；斜杠命令不做（与 skills 触发方向相反、无增量）；子智能体走**轻量人设**路线，不采用官方 agent-preset 插件组合（对"给主模型几个随叫随到的人设"过重）。
- **关联**：`docs/审查/2026-09-13-全项目对抗性审查.md`（本设计不含 index.ts 拆分，但新增代码按域模块落文件，不往 index.ts 堆）。

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| 场景 | `~/.dsh/scene-memory/` 一级目录（现状不变），名即场景名 |
| 场景记忆 | 场景目录内的 `.md`，启用场景的正文注入系统提示词（现状不变） |
| 场景档案 | 场景的可选配置：MCP 工具启停集 + 技能启停集 + 子智能体绑定清单 |
| 当前模式 | 至多一个场景处于"当前模式"：其档案被应用到运行时；退出恢复切换前快照 |
| 人设（子智能体） | `~/.dsh/subagents/<name>.md`：frontmatter（可选）+ 正文 = 人设提示词 |
| 子智能体运行 | 主模型经 `subagent_run` 工具创建的一次性 agent，跑完即弃 |

## 2. A 部分：场景档案

### 2.1 数据模型（扩展 `~/.dsh/tool-management/rules-index.json`，仍是唯一侧车）

```jsonc
{
  "version": 1,
  "rules": { /* 现状不变 */ },
  "groups": { /* 现状不变 */ },
  "active": null,            // 记忆注入的启用场景集合（现状不变，多选语义）
  "mode": {                  // 新增：当前模式
    "scene": null,           // 处于当前模式的场景名；null = 自由模式
    "snapshot": null         // 进入模式时的 { tools, skills } 运行时快照，退出时恢复
  },
  "archives": {              // 新增：每场景档案（缺省 = 无档案，卡片不显示模式按钮）
    "<场景名>": {
      "tools": { "<serverName>/<toolName>": true | false },  // 相对全集的启停覆盖
      "skills": { "<rootKey>/<skillName>": true | false },
      "subagents": ["code-review", "java-expert"]            // 绑定的人设名清单
    }
  }
}
```

### 2.2 切换语义（状态机）

- **进入模式 S**（显式用户动作，UI 按钮）：① 快照当前 MCP 工具启停全集 + 技能启停全集 → `mode.snapshot`；② 把 S 档案的覆盖应用到运行时（未提及的工具/技能 = 保持快照值）；③ 记忆启用集收窄为 `{S, _shared}`（用户之后仍可自由多选，不再受模式管）；④ 写 `mode = {scene: S, snapshot}`。全程走既有写锁串行。
- **退出模式**：恢复 `mode.snapshot` → `mode = {scene: null, snapshot: null}`。记忆启用集**不**恢复（保持用户当前选择）。
- **切换到另一模式 T**：先退出（恢复旧快照）再进入 T。
- **手动改动不自动回写档案**：进入模式后再手动启停工具/技能，只影响运行时；卡片上「保存到场景」按钮把当前运行时差异写回 S 的档案（显式动作，防静默覆盖）。
- **失败语义**：任一步应用失败（写 sidecar 失败等）→ 立即恢复快照并返回 `{ok:false}`（fail-closed，与修复后的 writeHistoryRetention 同哲学）。

### 2.3 应用机制（全部复用既有写通道，零新机制）

- MCP 工具启停 → 既有 `mcpm-tool-enabled` 的底层写函数（disabledTools sidecar，自带 .bak）；
- 技能启停 → 既有 skill enable/disable 批量通道（override provider 遮蔽，源文件不动）；
- 子智能体绑定 → 纯读取约束（见 §3.3），无运行时写。

### 2.4 UI（页面改名「场景记忆」→「场景」）

- 场景卡片三段：**记忆**（现状列表）/ **档案**（MCP 工具集、技能集两组启停 + 「从当前状态保存」）/ **子智能体**（人设多选）。
- 卡片右上：`设为当前模式` / `退出模式`（互斥，至多一个场景在模式中，模式中卡片有常驻标记）。
- `/scene-memory` 斜杠命令输出追加当前模式与档案摘要（命令名保留内部协议）。

## 3. B 部分：轻量子智能体

### 3.1 人设存储：`~/.dsh/subagents/<name>.md`（一个文件 = 一个人设，与场景记忆同哲学）

```markdown
---
description: 擅长 Java 后端实现与重构；需要写或改 Java 代码时调用   # 路由信号，缺省取正文首行
model: deepseek-v4-pro        # 可选；缺省继承主会话
tools: read, glob, grep       # 可选白名单；缺省不限制（用基础组合全集）
---
你是资深 Java 工程师。（正文 = 人设提示词，注入子代理 systemPrompt）
```

发现规则与场景记忆一致：两相扫描 + 指纹缓存；文件名 ≤64 字符、不含路径分隔符；**无 frontmatter 也能跑**。UI 上人设不入回收站（删了就是删了，v1 从简；文件操作走只读发现 + 手删）。

### 3.2 模型工具（2 个，工具总数 10 → 12）

- `subagent_list`：返回 `[{name, description, boundToCurrentScene}]`。
- `subagent_run{agent, task}`：
  1. 读人设；**场景绑定校验**（§3.3）；
  2. `ctx.agents.create({ sessionId: mint('dsh-tm-subagent-…'), parentAgent: 当前 agent, meta: { origin: 'subagent', parentSession, delegationDepth: 1, cwd }, agentOptions: { model? }, setup(agentCtx) { agentCtx.systemPrompt.section({ name: 'tool-management:persona', order: 3000, text: () => 人设正文 })；tools 白名单 → agentCtx.tools.restrict(...) } })`；
  3. 创建完成后**驱动**（官方契约「setup composes, never drives」）：向该会话投递 task 作为用户消息（投递入口 = Spike-1）；
  4. 等待完成、提取最终 assistant 文本（Spike-2），截断 ≤16 KiB 返回；
  5. `handle.dispose()`——停循环、注销、**移除会话**（不落 History 页，官方文档保证）。
- **确认门**：`tools/pre-execute` 对 `subagent_run` 默认 `ask`（花真 token），设置 `requireConfirmForModelSubagentRun` 可关——与 rule_manager_write 同模式。
- **并发**：v1 串行队列（同一时刻至多 1 个子代理运行），后续再放开；`delegationDepth: 1` 防递归套娃。

### 3.3 场景绑定语义（与记忆「无配置全启用」同哲学）

`subagent_run` 执行时取**当前启用场景集合**的 `subagents` 清单并集：并集为空 → 所有人设可用；非空 → 仅清单内人设可用，越界直接返回结构化错误并列出可用名单（不 ask、不猜）。纯读取约束，零运行时写。

## 4. Spike 清单（动工前一次性验证，全部只读/临时验证代码）

| # | 问题 | 方法 | 判定 |
|---|---|---|---|
| S1 | 创建后如何驱动子代理（投递用户消息的公开入口） | 读 dsh-agent-loop 的 Agent 驱动面 + ACP 桥的用法（它就是消费者范例） | 找到公开投递路径 → 采纳；找不到 → 降级方案：seed 平衡前缀 + 首轮由 setup 后立即 append |
| S2 | 如何等待完成并提取最终 assistant 文本 | 验证 `agent/status` / `turn-stopping` 事件 + 会话事件流读取（history-export 已有读法） | 任一路径可确定性判定"跑完" |
| S3 | 子代理是否自动继承全局场景记忆段 | 建最小人设跑一次，对比其提示词装配 | 继承 → 人设=正文+记忆；不继承 → setup 里显式补挂（设计已兼容） |
| S4 | setup 内 `restrict()` 白名单对子代理实际生效 | S3 同一次实验里带 `tools` 白名单跑 | 生效 → 采纳；不生效 → v1 砍掉 tools 白名单（人设仍可用），列入 backlog |

Spike 结论回填本文件后再进入实施计划。

## 5. 数据落点

| 内容 | 位置 |
|---|---|
| 场景档案 + 当前模式 | `~/.dsh/tool-management/rules-index.json`（扩展，见 §2.1） |
| 人设文件（真源） | `~/.dsh/subagents/<name>.md` |
| 人设索引/启停（如 v1.1 需要启停） | `~/.dsh/tool-management/subagents-index.json`（v1 不建，人设文件即真源） |
| 子代理运行会话 | 内存态 + `handle.dispose()` 移除，**不落盘、不进 History** |

## 6. 安全与门禁

- 新增写 op：`scene-mode-set`、`scene-archive-save`、`subagent-*`（如有 HTTP op）→ 走 service 级 `writeOps` 派生（C2 修复后的机制），不再手抄白名单。
- `subagent_run` 的 ask 门默认开；人设文件是磁盘文件，模型**不能**经工具改写人设（v1 无 subagent 写工具，人为编辑）。
- 模式切换与人设读取全部走既有写锁/读缓存；MCP sidecar 的 .bak 保护不变。

## 7. 测试计划（延续用户要求：真实浏览器场景）

1. 模式切换全流程（UI）：进入模式 → MCP/Skills 页核对启停已按档案生效 → 手动改一项 → 退出模式 → 核对恢复 → 「保存到场景」回写核对；
2. `subagent_run` 端到端：建一个人设（如"回声代理：复述任务并统计字数"）→ 聊天里让主模型调用 → 核对结果、ask 门、dispose 后 History 页无残留会话；
3. 场景绑定：档案绑定清单外的人设被拒（结构化错误）；
4. API 断言：新 op 的 token 门禁（带/不带 x-dsh-token）、mode 状态机失败回滚。

## 9. 未采纳方案

- **官方 agent-preset 组合当子智能体载体**：preset 是插件组合目录、会话创建时加入，与"运行中即用即弃"不符且对轻量人设过重（用户裁定）；preset 留作将来"重型模板"的正统载体。
- **每人设注册独立工具**（`subagent_code_review` 等）：工具清单随文件增删抖动，tool list 不稳定；单工具 + list 更符合官方单工具 + 参数路由的形态（与 ZCode Agent 工具同构）。
- **用 `tools/restrict` 控制人设可见性**：单工具形态下无 per-persona 工具可 restrict；改为 execute 时校验（§3.3），语义等价且更简单。
