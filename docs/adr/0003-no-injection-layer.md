# ADR-3：不注册 systemPrompt provider

- 状态：已采纳（v0.2）
- 日期：2026-09-12

## 背景

有观点认为"规则"应该做成每轮动态注入 system prompt 的能力（例如按当前问题召回相关规则）。但 DSH 的 KV Cache doctrine 明确：system prompt 段落一旦变化，从首个变化的段落起整段历史缓存失效；且 DeepSeek 上下文缓存要求完整匹配前缀单元，无部分命中。

## 决策

**不注册任何 `systemPrompt` provider**。规则只通过两种静态渠道进入模型：

1. **按需层**：作为 skill 目录条目（`name` + `description`），模型用 `skill` 工具按需加载；
2. **始终层**：`always:true` 的规则编译进 `~/.dsh/AGENTS.md`（字节稳定、首请求加载、会话内不变）。

## 理由

- 任何"每轮按当前问题动态变化"的内容进 system prompt，都会让缓存从注入点起完全失效，代价与全量重算相同。
- 静态投影的字节序列是确定的，改一次才变一次，缓存友好。

## 后果

- 规则内容在会话内是"静态"的；需要动态召回的检索/BM25 引擎明确不做（§12）。
- 始终层必须保证拼接结果字节稳定（确定性排序、无时间戳/计数）。
