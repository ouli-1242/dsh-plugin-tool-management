## 未发布（修复）

### 安全

- **明文密钥改为「没令牌就没有明文」**：`mcpm-reveal`（「显示密钥」）与 `mcpm-export`（配置导出）此前与普通读操作同路——配了 `token` 才校验，没配就只靠宿主栅栏。于是「能打开 GUI」就等于能取走全部密钥原文（实测可拿到 GitHub PAT、Tavily key）。现在这两个 op **只认证令牌**：没配 `token` 一律拒绝（`error.secret.noToken`），配了必须带对（`error.secret.badToken`）；同源 `Origin` 头不再算凭证。界面上「显示密钥」被拒时退回脱敏列表并单独给出原因（令牌不对时附带输入框，令牌存 localStorage、随请求以 `x-dsh-token` 发出），不再把整页刷成错误态。**升级影响**：想用「显示密钥」必须在本插件配置里加 `token`（或设 `DSH_PLUGIN_TOOL_MANAGEMENT_TOKEN`）并在界面填入同一个值。

### 修复

- **技能页「移除来源 / 恢复读取」是死按钮**：客户端 `OP_BY_PATH` 缺 `/source-remove` 与 `/source-restore` 两条映射，`callApi` 直接 reject、弹窗又吞掉了拒绝——按钮点下去毫无反应（宿主侧两个 op 本身没问题）。补上映射；同时把这两个 op 补进 `writeOps` 门禁清单（漏了意味着配了令牌也不会被要求带令牌）。
- **「整理补丁」修好基准后重新上线（只留按钮，不留那几段字）**：`mcpm-compact` 删掉补丁文件里多余的启停覆盖块——被后面盖住的旧块、以及值与 insert 行相同的 no-op 块；**生效状态不变**，insert 行与带配置的覆盖块都不动，删前自动备份（保留 5 份）。界面只在页首留一个「整理补丁」按钮（含二次确认与"删了几个 / 本来就没有"的如实回执），**不再显示**行上的「启停覆盖 ×N」标记与告警条（用户裁定：那几段字不要）。基准状态现在只能由 `src/mcp/override-blocks.ts` 自己从 insert 行读（`insertBaseRows`），调用方传的是"另一份补丁文件的内容"，从结构上堵住第一版传错基准的路。第一次事故见下方「事故记录」。
- **`rules-toggle` 不传 `enabled` 时静默 no-op 却返回成功**：旧实现缺省时「沿用当前值」，还照样刷新 `updatedAt` 并回 `ok:true`，按「toggle = 翻转」理解的外部调用方会以为自己改了状态。现在缺参数明确拒绝（`error.rules.invalidArgs`）、不写盘（界面不受影响，它一直显式传值）。

### 事故记录（2026-09-14，「整理补丁」第一版）

「整理补丁」第一版上线当天就出过一次事故：**点完它之后，6 台 MCP 服务全部变成启动状态**。根因是收敛计划拿错了「基准状态」——它需要的是 **insert 行自带的 `disabled`**（默认不存在 = 启用），而实现里传进去的是 `parseRows()` 合并覆盖块之后的**生效值**。生效值恒等于最后一条覆盖块（decider）的值，于是"decider 的值等于基准"永远成立，**每一个 decider 都被判定为多余并删掉**，包括决定"这台服务是停用的"那一条。

同一条错误在当时的界面数字上留了痕迹：告警里每个 id 的"多余块数"都比真实值多 1（`serena ×1`、`github ×4`、`context7 ×6`、`fastgraph ×3`——连只有一条覆盖块的 serena 都报"多余 1 个"）。

修法不只是改那一处传参：基准现在由模块内部从 insert 行读，接口收的是"另一份文件的内容"（`planOverrideCompaction(content, otherFileContents)`），调用方**没有**办法再传一个现成的状态值进来。补丁文件的其它写入路径未变：`mcpm-set-enabled` / `mcpm-set-all` 仍然只写带标记的块并先清掉自己的旧块（幂等）。

### 变更

- **「已移除的来源」并入回收站，分「目录 / 技能」两部分**：原来那一段是主列表下面的一块 `dsm-table` 行样式的卡片，列宽与技能表不匹配（路径挤成 120px、按钮挤进 90px 一列），观感是坏的；而且只有「恢复读取」，没有出口。现在被移除的来源不再占主列表，改为进「回收站 → 目录」（回收站入口的徽标显示「技能 N · 目录 M」），两边都能恢复；**目录也能永久删除**——删的是插件里的来源记录（`customRoots` + 相关策略键），磁盘上的文件夹与文件一个字节都不动，这一点写进了确认弹窗。按约定发现的外部来源（`~/.agents` / `~/.codex` / `~/.claude`）没有记录可删，因此只显示「恢复读取」（宿主侧据此给行加 `custom` 标记，界面按它决定要不要给永久删除按钮）。

## v0.6.0（2026-09-14）

**主题：宿主兼容体检。** 插件不再靠「比对官方源码文本」判断能不能动宿主数据，改为「查模块实体 + 探能力」，并把结果做成设置页里的「兼容」页；同时修掉归档会话的工作区归属、技能来源权限语义两类真缺陷。

### 新增

- **「工具 → 兼容」页（第 8 个页签，只读）**：宿主版本与要求范围、插件适配版本、能力可用数、**每个宿主动作走哪条路径**（宿主原生入口 / 插件适配层 / 不可用）、已降级能力与原因、模块实体是否与宿主同一份、阻塞项清单，以及命令行体检入口。数据来自新 op `compat-status`，页面可「重新检查」。
- **`node scripts/doctor.mjs`**：命令行版同一份体检，打印模块实体归属与宿主能力探测结果。
- **`node scripts/host-deps.mjs`（`--fix` / `--restore`）**：把插件用的 `@deepseek-ai/*` 逐包改为指向宿主安装的 junction（原始副本备份到 `.host-deps-backup/`）。两边的包不是同一份物理模块时，`instanceof` / `===` / symbol 查找都不成立，「适配宿主实现」只能退化成猜。
- **归档分组可重建**：工作区登记被 DSH 删除后（删登记不删目录、不删会话），归档列表按会话目录自动重建分组，标「工作区已移除」/「未登记的工作区」；目录仍在时给一个「重新登记为工作区」按钮（只在用户确认后调用宿主自己的接口，**只新增登记，不动文件与会话**）。
- **恢复归档顺带恢复归属**：恢复会话后按会话目录把它挂回工作区记账（新增登记 / 复用已有登记 / 挂回会话），响应里带回 `registered` / `attached` / `skipped`，界面按结果显示一句话结论。此前恢复出来的会话在宿主侧没有归属，只会掉进「未分组」。
- **场景可绑定一份提示词预设**：场景表单里选一个（单值字段 = 天然单选）。绑定前校验预设存在（不存在直接拒绝，不留悬空绑定），预设事后被删则场景卡片标「预设不存在」。**切换场景会直接改写 `~/.dsh/AGENTS.md`**（见下条）。
- **切换场景直接改写 `~/.dsh/AGENTS.md`**（同日，**反转**本轮早先「只注入一段、不碰文件」的决定 —— 用户裁定：「切换场景，对应的提示词直接把 AGENTS.md 直接修改」）：启用/切换场景、改绑预设、编辑"正在驱动基线的那份预设"的正文，四个动作都会把那份预设**真写进全局基线**，与「提示词」页的「应用」同一条路（覆盖前多代备份到 `agents-md/__last-applied__/`）；**关掉场景时按原文恢复"进场景之前"的基线**（那份可能是用户手写的，不一定对应任何预设）——快照存 hub 的 `scene-baseline.json`，恢复后清空，连续切场景不会覆盖快照。相应地，`tool-management:scene-prompt` 注入段**已删除**（真改文件后再注入一遍会让同一份正文进上下文两次，且用户手改基线后还会被重新注入）；绑定关系只保留只读投影，用于页面「生效中」标记与"文件是否已同步"的判断（内容一致时**不写盘**）。同步逻辑提成独立模块 `src/scene-prompt-sync.ts`，可在临时目录上用真实服务端到端验证。
- **提示词预设库：新建即可写正文、编辑可改 id**：新建弹窗是「id + 正文文本框」（外加「或从现有预设复制」下拉，选中后把那份正文填进文本框，仍可继续改），不再是那个容易被当成搜索框的「复制来源」文本输入；编辑弹窗同样有 id 与正文两个字段。**改 id = 目录改名**（正文随目录一起走，目标已存在则拒绝、不合并），改名成功后宿主顺手把场景绑定一起改名（新增 op `rules-rebind-prompt`），不留悬空绑定。
- **「生效中」以场景绑定的那份为准**：场景启用且绑了提示词预设时，**提示词页把场景绑的那份标成「生效中」**（用户裁定：「场景启动了，提示词内生效中的应该是场景选择的那个」），页面顶部写明来源（`当前：life（场景「A」）`）；切换场景会把它写进 `AGENTS.md`，所以「文件里是它」这个降级标记只在用户手改过基线、或写入失败时才会出现。
- **正在生效的提示词预设不能删除**（用户裁定）：提示词页把「生效中」那行的**删除按钮禁用**并给出原因（悬停可见），宿主侧 `agentsmd-remove` 也**拒绝**删除它——生效 = 启用的场景绑定了它，否则 = 文件内容就是它；两者都不是的预设照常可删（被场景覆盖、只躺在文件里的那份也允许删）。删除按钮只是提示，真正的门在宿主：模型调用或旧页面缓存都会被挡住；被挡住时界面会把宿主返回的原因显示成错误条（`doRemove` 此前丢弃了响应，是静默失败）。判定失败时放行并记 warn——删预设不动 `~/.dsh/AGENTS.md`，最坏只是少一份副本。
- **技能导入弹窗新增「选择文件夹」**；人设的**工具白/黑名单按官方 Agent 预设分组**展示（同一工具属于多个预设时在对应分组各出现一次，勾选状态共享），不再把所有非当前会话工具统一标成「当前会话不可见」。

### 变更

- **兼容判定换底座**：删除「按源码文本比对官方实现」的门禁（上游改一行注释就会让归档/恢复/删除整体拒绝服务）。现在按能力路由——**有原生入口走原生、没有走受检适配层、都不行才拒绝**；拒绝信息写明**缺什么能力、后果、怎么修**，并且**永远发生在任何写入之前**。宿主本来就没有的可选原生槽位不算降级（由插件自己顶上）。
- **技能来源权限语义修正**（两组来源的权限正好相反）：默认来源 `DSH 技能`（`~/.dsh/skills/`）与 `导入技能`（`~/.dsh/tool-management/skills/`）**必须读取**——不可移除、**也不可停用**（停用等于「读出来但不可调用」，与「路径不能不读取」冲突）；但**里面的技能可以删**（进回收站，可原样恢复）。外部 Agent 目录与自定义目录相反：**可以停用或移除**（不再读取），但里面的技能**只读、不能删**。旧版本写过的 `sources.hub` / `removedSources` 残留策略位在读取时被丢弃。
- **用户数据搬出插件目录**：归档账本 `history-archived-at.json`、保留期 `history-retention.json`、工作区登记快照 `history-workspaces.json` 移入 `~/.dsh/tool-management/`（旧位置是插件目录 `data/`，启动时自动搬入，只搬不删、绝不覆盖）。npm 安装下 `dsh plugin update` 会整体替换插件目录，账本放那里会连累保留期基线。
- **归档服务改为独立门面**：`cordis.patch.yml` **只插入本插件**——不再禁用官方 `workspace` / `session-projection-cache`，不再插入竞争 provider，也不按包名推断兼容性。归档时刻改由官方持久化事件打点；宿主自带删除屏障时不包裹投影缓存，缺屏障时才包裹并在卸载后原样还原。
- **弹窗按钮统一**：全插件 24 处弹窗的「取消 / 关闭」只留在右上角（外加 Esc 与点遮罩），底部只留主操作。
- **语言跟随宿主**：客户端显式注入 `locale`（`dsh.client.inject` 精简为 `@deepseek-ai/dsh-client-locale`），面板与页签名不再恒为中文；**会话页**与 **AGENTS.md（提示词）页**整页接入中英词典（新增约 100 条词条）。`check:i18n` 新增一项检查：**代码里以字面量引用的键必须都在词典里**（挡住「界面直接显示原始键名」）。
- **AGENTS.md 预设「应用」保留 5 代备份**：写入 `__last-applied__/AGENTS.md.bak-<时间戳>`，按时间轮转只留最近 5 份（旧机器读取的 `__last-applied__/AGENTS.md` 照旧维护）。单槽位备份下连点两次「应用」会永久覆盖用户手写的原始内容。
- **提示词预设 id 口径放宽**（用户裁定「id 应该什么都能写」）：不再限定小写字母/数字/连字符，中文、空格、下划线、点都可以。id 即目录名，因此只保留文件系统硬约束——不含 `/ \` 与 `< > : " | ? *`、不以点开头、不以点或空格结尾、不是 `.`/`..`、不是 Windows 保留设备名（`con`/`nul`/`com1`…）、不含控制字符、≤64 字符，以及一个保留字 `__last-applied__`（「应用」的备份槽）。口径收在新的单一模块 `src/agents-md/preset-id.ts`，AGENTS.md 预设库与场景绑定（`scenes[].prompt`）共用，避免两处漂移；导入预设的 id 也不再被压成 slug。
- **场景启用改单选**：除保留场景「全局」外**同时只能启用一个场景** —— 服务端拒绝多选（`error.rules.singleSceneOnly`，旧的 `all:true` 形态一并拒绝），界面把其余场景的开关**置灰**并说明被谁占用；`rules-create-scene` 会把历史默认 `active = null`（旧语义「全部启用」）**收敛成显式数组**，因此**新场景默认不启动**，并把 `collapsedActive` 回传界面如实提示；「切入此模式」现在会**同时启用该场景**（档案、记忆、提示词一起生效）。存量 `active = null` 且多个场景在场的状态**仍按旧语义读**（记忆段注入全部），场景页给一条显式「收敛为单选」按钮，而不是静默改写注入范围。
- **模型/脚本入口语义收紧**：`history-retention-set` 拒绝小数（原来 1.5 被静默取整成 1）并在错误里回显收到的值；`rules-set-active` 必须显式传 `all:true` 或 `scenes:[…]`（无参不再静默把注入范围清成空）；`mcpm-set-enabled` 的停用分支幂等（不再每点一次就往 `cordis.patch.yml` 追加一条重复项）；`skill_manager_create` 的落点与界面「创建技能」一致（都落 hub）；`history-import` 改为经宿主 `agents.create` 创建会话并回读校验，导入失败如实报错（会话 id 形态变为 `session-<uuid>`）。
- **写操作门禁**：HTTP 路由先过宿主的 `connection.requestRejection`（Host 必须是回环 / LAN IP 字面量，叠加 browser-session cookie）；宿主服务不在场时退回**本地判定**（只要求回环 Host + 非跨站 Fetch + Origin 与 Host 同源，**不含 cookie 鉴权**，比宿主栅栏弱）。`mcpm-reveal` / `mcpm-export` 这类会吐明文密钥的 op 额外要求请求带 `Origin` 头。显式配置的 `token` 是脚本 / 局域网的逃生门：令牌正确即视为已授权（并跳过栅栏）。

### 修复

- **进出场景模式会静默改写技能策略（数据污染）**：快照与目标状态用的是**生效状态**，写回的却是**显式策略记录**，两者不等价 → 进出一次模式就会把用户从未启用的技能写成启用、把显式启用的改写成显式停用。现在扫描一次同时给出「生效 / 被同名覆盖 / 全量键」，快照只取生效项，写回时跳过被覆盖的副本、且**已经处于目标状态的技能不再写**。修复后同一实验下状态文件与基线逐字节一致。
- **导入技能里删掉的技能拿不回来**：回收站元数据把非项目级来源记成了项目级，恢复时被判「原项目不在活动工作区」而拒绝。现在按作用域分岔，用户级来源按 key 重新解析路径（不信任元数据里的旧路径）。
- **技能回收站显示字面量 `undefined`**：项目级来源缺名称/路径时不再拼空值，统一回退到来源显示名。
- **面板不随宿主语言切换**、**会话页与 AGENTS.md 页整页硬编码中文**、**两个词条键写错导致界面露出原始键名**（`mcp.field.entryId` → `mcp.detail.entryId`）。
- **`subagent_run` 的确认门早于参数校验**：人设不存在时不再先弹确认卡（批准后才报错），直接让工具体给出真实错误。
- **删除链路的前置实现检查**：删除序列依赖官方声明为 private 的方法，此前失败点可能落在链路中段、留下「转录已删但归档标记还在」的部分状态。现在在任何破坏性步骤（含写屏障）之前校验所需方法，缺失即快速失败并提示更新插件。
- **英文界面下兼容页的结论条仍是中文**：`compat-status` 的 `summary` 由服务端拼中文，英文界面直接照抄。现改为**客户端按当前语言拼**（新增 `compat.summary.ok` / `compat.summary.degraded` 两条词条），服务端那份 `summary` 只留给日志；并加一条本地化回归断言：英文词典下渲染兼容页，结论条不得出现中文字符（只锁"不许露中文"，不锁措辞）。
  > 仍未本地化：降级项的 `label` / `detail` 与阻塞项文本仍由 `src/compat/probe.ts` 输出中文。宿主一切正常时页面上看不到它们（多数机器就是这个状态），一旦真降级，英文界面会中英混排。
- **`history-workspace-register` 漏了 token 门禁**：它会新增一条宿主工作区登记，属写操作却不在 `WRITE_OPS` 里 —— 配置了 `token` 时它不校验 `x-dsh-token`（仍受宿主栅栏约束）。现补入清单，与其它写 op 一致。
- **两处与实际行为不符的界面文案**：AGENTS.md「应用」的说明补上「备份**保留最近 5 代**」；创建技能的确认卡原写 `DSH_HOME/skills`，而该工具已改为落 `~/.dsh/tool-management/skills/`（与界面「创建技能」同根）。

### 已知限制（本版）

- **浏览器交互验收仍未跑**（宿主要 launch token）。能进 CI 的是导出契约、装配与渲染、语义契约三层，**挡不住交互行为**；破坏性路径（归档 → 恢复 → 永久删除 → 保留期清理）仍需人工在实机点一次。
- **与 `@michengai/dsh-archive-manager` 未做双安装验证**，不宣称与任意版本共存。归档兼容层仍是**有限兼容层**，不是零侵入：本地恢复/删除访问经检查的宿主内部状态；宿主缺自带删除屏障时会包裹投影缓存的 `put` / `write`（卸载后还原）。
- **依赖去重只处理「两边都有」的包**；只有插件侧存在的包会报 `SKEW` 且**不被改动**。生产布局（`profiles/<name>/node_modules/<plugin>`）不需要跑 `--fix`，开发 `link:` 布局才需要。
- **能力探测的版本指纹**取自 `@deepseek-ai/dsh-workspace` 的 `package.json`；官方拆包或改名时指纹退化为 `unknown`（此时仍按能力判断，不按版本）。能力评估有 5 秒 TTL，兼容页与写路由最多滞后 5 秒。
- **硬编码中文未清零**：`node scripts/i18n-debt.mjs` 当前报 **214 条**（提示词页 15 条 + 199 条散落在未按页统计的组件与共享壳中；会话页已清零）。该脚本按页面函数分区统计，因此「按页」只能覆盖它认得的页面。
- **官方 Config schema 缺失**：插件仍以 `{name, inject, apply}` 形式加载，`config.*` 裸读，没有加载期校验与默认值。
- **场景提示词的三个边界**：① 保留场景「全局」也可手工绑定提示词（写在 `rules-index.json` 的 `scenes.global.prompt`），但它只在**没有任何场景启用**时生效，界面暂不暴露该入口；② 场景提示词**不计入记忆字节预算**（预算只管记忆段），体量由你自己控制；③ 历史 `active = null` 的多场景状态要你点一次「收敛为单选」才进入单选语义。
- 其它长期边界见下方「长期约束与边界」。

## 长期约束与边界

跨版本有效，改代码前先读。

### 非干扰原则（红线）

任何时候不得为插件功能改写 DSH 原生文件的语义、不得给原生段改名或改序、不得让注入内容破坏前缀缓存契约。违反任意一条即视为架构回归。

- **前缀缓存友好**：注入段文本只由「启用场景 + 文件内容」决定，逐字节稳定；场景切换或编辑记忆只变化一次。段内不得出现时间戳、计数、相对时间等每轮变化的内容。
- **数据落点**：插件**不在自己的安装目录存用户数据**（npm 安装会整体替换该目录）；用户数据一律在 `~/.dsh/tool-management/`。稳态零写入，唯一会「覆盖」的是运行期手改这些文件——请在停止 `dsh web` 后再改。
- **生效方式**：插件由宿主启动时加载 `lib/`，**改动需重启 `dsh web`**（patch 热重载不会重新 import 插件模块）；`lib/` 不入版本库，克隆后先 `npm run build`。

### 治理与兼容边界

- **子代理有两条通道**：本插件的 `subagent_run` 走确认门与场景人设绑定；DSH 官方的 `subagent` / `subagent_fork` 是宿主能力，**没有确认门、也不认这套人设**。本插件的治理只覆盖 `subagent_run`。
- **归档兼容层**：官方目前没有完整的公开归档扩展接口，实际执行的是受检适配层（访问经检查的内部状态）。它是**有限兼容层**，不等于零侵入，也不等于与官方实现解耦。
- **契约测试的边界**：契约测试断言语义契约而非实现抄写，替代不了真实行为验收；浏览器交互与破坏性路径仍需人工在实机确认。
- **尚未验证**：与 `@michengai/dsh-archive-manager` 的双安装；官方工具在 `never` 会话下的行为；服务器「后加载」场景；`subagent_run` 参数不可见时的线上抓包复核。

### 升级 DSH 之后（按序执行）

```bash
node scripts/doctor.mjs          # 1. 模块实体是否同一份 + 宿主能力是否齐备
node scripts/host-deps.mjs --fix #    出现「两份拷贝」时执行（改动的是 node_modules，不动源码）
npm test                         # 2. 契约测试（13 组，跑 lib/ 产物）
# 3. 打开 设置 → 工具 → 兼容：确认宿主版本、降级项、每个动作走哪条路径
# 4. 破坏性路径人工回归：归档 → 恢复 → 永久删除 → 保留期清理
```

宿主缺某个包时，插件会拒绝受影响的动作并说明原因，不会「猜着写」。
