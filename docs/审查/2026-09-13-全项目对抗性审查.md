## Standards（代码质量轴）

### 总评

最痛的结构性问题有三层：**发布产物 lib/ 被 git 跟踪且已在同一提交内与 src 漂移**（构建诚实性已实际破损）；**src/index.ts 2498 行单函数域**把五个域的 op、鉴权、YAML、历史、命令全部关在一个 apply 闭包里，是典型的 Divergent Change；**五域各自复制演化出一套私有基础设施**（写锁、TTL 缓存、原子写、错误形状、日志通道各 2–5 份），用户要的"统一、好维护、好拓展"恰好被这三点抵消。

### Critical

1. **【hard：构建诚实性】lib 与 src 同提交漂移**。`git status` 干净，但 HEAD 中 `lib/skills/core.js`（2621 行）≠ `src/skills/core.js`（2956 行），`lib/history/workspace.js` 同样落后 77 行——已提交的发布产物落后于自己的源码。改法：lib/ 移出版本库（.gitignore 已有先例注释，`prepublishOnly` 已自动构建）或 CI 加"构建后 diff 为空"门禁。专项5 结论：sync-client.mjs 用复制而非 tsc 是因为 tsconfig:23 显式 exclude 了 client.js（浏览器 bundle 要求逐字节保真，tsc 的 allowJs 重排会产生无意义 diff）——脚本本身合理，真正的问题是 lib 整体入库 + `lint` 只 `node --check` 10 个产物中的 2 个。
2. **【hard：token 门禁漂移】WRITE_OPS 漏了 3 个写 op**。index.ts:229-251 只列 9 个 `rules-*` 写操作，而 rules/service.ts:1765-1767 注册了 `rules-trash-remove`（永久删除）、`rules-attach`、`rules-detach`——配置 token 后这三个破坏性操作不受 `x-dsh-token` 保护。根因是 op 表与写操作白名单是两份手工清单（Shotgun Surgery）。改法：ops 注册时带 `{handler, write:true}` 元数据，白名单自动派生。
3. **【bug】core.js:2596 引用未定义变量**。`skillDetail`（:2586 起签名 `(keyOrRoot, name, options)`）中 `` error: `未知技能来源: ${key}` ``——作用域里没有 `key` 绑定，未知来源路径会抛 ReferenceError 而非预期的 `{ok:false, code:"error.root.unknown"}`。无测试套件，这类错误只能靠运行撞上。

### Important

4. **【judgement】index.ts 单文件 2498 行 / any 密度**。apply() 内嵌 51 个 handler（index.ts:1712 起）+ YAML 生成/解析（556–814）+ sidecar + 鉴权门 + 工具注册 + 4 个斜杠命令；grep 到 68 处 `: any`，51 个 handler 全是 `(args: any)`，strict TS 的边界保护为零。改法：按域拆 `mcp/patch.ts`（YAML+MCP ops）、`history/ops.ts`、`api/route.ts`，给 op 协议定义 `OpArgs` 映射类型。
5. **【专项1】TS/JS 混用：约定三分之二、包袱三分之一**。README 声明"宿主 TS + 技能 core 纯 JS"是约定；但 `history/workspace.js`/`projcache.js` 是上游 dsh-archive-manager 的 esbuild 产物直接当源码（`//#region`、`void 0`、tab 缩进），且 `src/` 内混着 `core.js`（2956 行，无类型）与 `service.ts`（439 行薄适配，`ctx: any` 贯穿）。实际代价：core.js 的返回形状只能靠人肉对齐，rules/service.ts:174 不得不再声明一遍 `ParsedSkillDoc`。建议：至少给 core.js 开 `checkJs`，workspace/projcache 保留但注明"原样移植"。
6. **【judgement】五域重复基础设施清单（专项3，均验证过行号）**：写串行队列 x3——index.ts:256 `withWriteLock`、skills/service.ts:324 `enqueueMutation`、rules/service.ts:1006 `enqueueMutation`（逐字相同）；TTL 缓存 `{at,value}` x5——index.ts:949/985/1040、rules:964、skills:310；`message()` x4（index:254、skills:39、rules:79、agents-md:44）；原子写 x2（core.js:855、rules:247），而 index.ts:937 `writeJsonFile` 与 agents-md:160 是裸 writeFile——同域四种持久化强度；win32 identity x3（readonly-discovery:8、core:636、rules:83）；`unquote` 同名异义（index:615 带类型推断 vs core:769 纯字符串）；批量 target 校验两份（index:1686 vs workspace.js:141）；场景名校验前后端两份（rules:62 vs client.js:1568）。全部可收进共享 util。
7. **【judgement】错误/返回/日志约定不统一（专项7）**。skills 成功返回 `{ok:true,data}`、rules/index 返回扁平 `{ok:true,...}`（index.ts:1733/1739 注释自认）；错误有三种形状：rules/skills 带 `code+params`，index.ts 与 agents-md 只有中文 `error`——所以 `translateError`（client.js:889）对 MCP/History/AGENTS.md 页完全失效；日志四通道：skills 写 JSONL 文件、history 子类用 `ctx.logger`、index/rules 只 console.error，README 宣称的"运行日志"其实只有技能域在写。
8. **【judgement】client.js 五页脚手架重复（专项6）**。MCP(514)/AGENTS.md(629)/Skills(1095)/History(1465)/SceneMemory(2016) 各自手写 title-row+VersionBadge+summary 三格+filters+空态+确认弹窗；操作反馈有 4 种实现（msg 横幅 / error Modal / result 横幅 / toast+横幅，见 535、614、1048、2050）；i18n 也不统一——Skills/记忆页走 `t()`，MCP/History/AGENTS.md 硬编码中文。缺 PageHeader/SummaryBar/ConfirmModal 三个共享组件。

### Minor

9. **命名（专项4）**：模型工具三种前缀并存 `skill_mcp_manager_*`/`skill_manager_*`/`rule_manager_*` vs `agentsmd_list`（index.ts:2185，唯一不带 `_manager` 的）；`rules-*` op 名保留为内部协议是 README 声明的决定（不算 hard），但 README:61 "模型工具 10 个"实为 12 个；index.ts:220 注释仍写 `DSH_SKILL_MCP_MANAGER_TOKEN`，代码（228 行）读的是 `DSH_PLUGIN_TOOL_MANAGEMENT_TOKEN`。
10. **死代码 / Speculative Generality（专项8）**：rules/service.ts:98 `getGlobalAgentsMdPath` 自注"历史遗留"，且 index.ts 装配时根本没传、服务体内也未用；RulesService 的 `_invalidate/_renderActiveScenes/_sceneMemory`（163–168）标注"测试用"但测试套件不存在；core.js:1524 `setSkillEnabled` 是纯转发（Middle Man）；client.js DICT 里的 `root.gemini/cursor/opencode/ccswitch` 与整组 `error.proto.*` 键（752、838）来自上游已裁剪的协议。
11. **index.ts 手写 YAML 解析**（604 注释已声明 known limitation，约 200 行）：可接受，但它是 index.ts 膨胀主因，随拆分移入独立模块。
12. **index.ts:341 `writeHistoryRetention` 吞错后仍返回 ok:true**——与其余域"失败必报 {ok:false}"相悖。

### 可拓展性结论（专项9）

新增第六域至少动 5 处——index.ts（WRITE_OPS、handlers、工具注册、pre-execute 门）、client.js（ToolsSection tab + 新页 + CSS）、README。handlers 映射虽集中，但装配有三种风格混用（`...skillsService.ops` 展开 / agentsmd 内联箭头 / history 闭包），且无 ops→页面→工具的域注册表接缝；新增技能来源反而只需在 core.js `userRoots()` 加一项（该接缝是好的）。

### 「无测试套件」的复核结论

`skillDetail` 的 ReferenceError 与门禁漂移恰好都是断言级测试可拦的；在当前 13k 行、五域复杂度下，README 文档化的"无测试"决定已不成立，建议至少给 ops 协议层加冒烟测试。

### 最值得做的 3 件事

1. **让 lib/ 不再入库或加"构建即同步"CI 门禁** → 发布产物与源码已在 HEAD 漂移，用户拿到的代码 ≠ 看到的代码 → 半天。
2. **ops 注册表带 `write` 元数据并派生 WRITE_OPS** → 修复 token 门禁漏 `rules-trash-remove` 等 3 op，且消灭六域最常见的散弹式修改 → 半天。
3. **提取共享 util（message/写锁/TTL 缓存/原子写/identity）+ 拆 index.ts 为 mcp/history/api 三模块** → 五域风格统一的前提是底座唯一，any 边界顺手换类型 → 2–3 天。

## Spec（官方对齐轴）

**基准**：官方文档站（develop/basic、/tool、/config、/publish 均可达）+ 项目 node_modules/@deepseek-ai/* + 实机宿主 `~/.dsh/profiles/node_modules/@deepseek-ai/*`（loader 与宿主服务在此，项目内 node_modules 不含 loader）。

### 总评

插件在官方有公开契约的各条缝上贴合度高——对象插件形状、`ctx.tools.register(defineTool(...))`、`tools/pre-execute {kind:'ask'}`/`guard`/`restrict`、`SystemPrompt.section`、`dsh.bundle.patch` 与 `dsh.client.platform/inject` 清单、exact 路由、projcache 的 `Config` 字段，均逐一验证为官方正途。最高风险集中在**服务替换**：两个子类大量触达官方 `.d.ts` 明示 TS-private 的成员，官方从未承诺该继承面；其次是缺少官方要求的 Config schema 导出。

### Critical（确认违反官方契约/高危）

1. **workspace 子类触达官方私有面**。`src/history/workspace.js`（ArchiveWorkspaceRegistry，:272 起）读写 `this.requireState/readSessionHeader/enqueueOperation/sessionKnown/requireTable/setState/headers/sessionPaths/invalidSessionPaths/listStoredHeaders/indexHeader/entities`（:340,343,489-538,656,675-681,752-754,796,908,927）；对照 `node_modules/@deepseek-ai/dsh-workspace/lib/types/index.d.ts:56-64,131,150-162`，以上全部声明为 `private`。公开面仅 `create/get/list/delete/insertBefore/archivedSessionIds/archiveSession/resolveByPath`。官方无"可替换"承诺 → 确认越界。
2. **projcache 子类同理**。`src/history/projcache.js:216-222`（`[Service.init]` 内写 `this.table`、调 `this.installWritePath()`）、:300（`super.put`）、:315（`this.requireTable().delete`）对照 `dsh-session-projection-cache/lib/types/index.d.ts:57,145,155,156`（均 private）；且注释自认依赖"`super.write` 返回后不再异步落盘"的上游实现细节（:273-275）。另：`putSoft` 垫片引用的 `SessionProjectionCache.prototype.putSoft` 在锁定的 0.1.5-rc.2 运行时中 grep=0（不存在），注释对 rc.2 行为的描述与本地证据不符（防御性写法，无功能故障，待确认其历史出处）。

### Important

3. **缺官方 Config schema**（确认违反）。官方 /develop/basic/config 要求导出同名 Schemastery schema（"不要导出普通对象作为 Config"）；插件 `src/index.ts` 仅有 `export default {name,inject,apply}`，config.token/presetsDir/rulesRoot/stateDir/rulesMaxBytes/maxBodyBytes（:222,275,315-321,2298）裸读，无加载期校验与默认值。cordis 本身支持 Standard Schema 校验（`cordis/src/registry.ts:103`）。
4. **patch 语义核实（多数属实）**：`disabled:true` 生效（`cordis-plugin-loader/lib/index.js` Entry.`disabledOf`→`Boolean(options.disabled)`，`_disabled` 沿祖先链传播）；`!!js` 的"`Entry.disabled` 是未缓存 getter、触碰自身行会重入"的警告**属实**（:360-362 `get disabled(){return this._disabled(this.options)}` 无缓存，:374-376 每次 `evaluate`），`id!=='…'` 先短路防递归的顺序论证成立；`ctx.loader.entries()` 存在（:170）。微偏：表达式并非只在 activation 求值，而是**每次读取都重算**。`config:{writeEveryEvents,writeIntervalMs}` 正是官方公开 Config（`dsh-session-projection-cache/.../index.d.ts:37-42`）✔。
5. **inject 与实际使用漂移**：`inject:['timer',…]`（index.ts:200）但 `ctx.timer` 全文 0 次使用；`'sessions'` 已 inject 却仍 `ctx.get('sessions')` 探测（:1963,1996）。违反"inject=必需服务"的官方语义，timer 缺失会无谓拒绝加载。
6. **本地类型漂移（已漂移 2 处）**：`writeText(path,content,encoding?,flag?,policy?)`（index.ts:59、调用 :533）vs 官方 `dsh-fs/lib/types/index.d.ts` `writeText(target, content, expected?: FsWriteIntent, signal?: AbortSignal, sandboxPolicy?)` —— 第 3/4 参名义完全不同，第 5 参按位置恰好对位；`prepareDocument():Promise<unknown>` vs 官方 `dsh-settings/.../index.d.ts:193 Promise<string|undefined>`，插件径直当 home 路径用（:417-423）。`WebServerService.register({kind:'exact'})` 与"duplicate (kind,path) throws"均与官方 `dsh-host-webserver/.../index.d.ts:30-34,90` 一致 ✔（此处反而是官方证据最硬的一条）。

### Minor

7. 工具命名：官方无前缀强制（/develop/basic/tool 无命名约定，仅 `run_code` 保留名），`skill_mcp_manager_*` 等合规；`defineTool` 六字段与 `output` 强制项全部符合 `dsh-tools/lib/types/schema.d.ts:178-239`。审批/禁用全走官方缝（`PreToolDecision{kind:'ask'}` index.d.ts:419-425、`ToolGuard`:485、`ToolRestriction`:475）✔。
8. systemPrompt：`section({name,order,text:provider})` 为官方 API，`SECTION_ORDERS` 2900→5000 空档属实、order:3000 合法；`agent/created|disposed` 为官方事件（dsh-agent runtime-types.d.ts:224,235）。手动 `emit('system-prompt/change')`（provider.ts:112）越过了官方"注册/注销自动 emit"约定，多余无害。per-agent 双注册遮蔽策略即官方 scoped-shadow 语义。
9. `dsh.client.platform`（必须 string）与 `dsh.client.inject`（string[]）为官方协议（`dsh-client-modules/lib/index.js:139-146`）✔；client.js 的 localStorage 用法无官方客户端约定可对照（待确认）。HTTP `{op,args}`、`x-dsh-token` 为插件自定义，官方无冲突规范（待确认）。

### 升级韧性评估（0.1.5-rc.2 → 0.2.0 官方升级时最先坏的三处）

1. `dsh-workspace` WorkspaceRegistry 私有成员改名/增删（纯 JS 子类无编译期保护）→ workspace.js 运行期 undefined 崩溃或索引语义错位。

### 官方已提供但插件重写

- 临时文件+rename 原子写（rules/service.ts:246-263、agents-md/service.ts、index.ts）——官方有 `dsh-atomic-write`
- retention/archivedAt/agents-md-presets 的 JSON sidecar——官方有 `dsh-storage-domain` 域机制（projcache 一侧已正确使用）

### 官方确无、必须自写
