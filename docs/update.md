## 0.9.5 - 2026-09-18

- **注入的框架改成 markdown 四级结构，动作句加粗、放到最前**：以前五个域共用一句「以下是本机插件的X（取代…）」，动作藏在句子中间，五条又长得相近 —— 第一轮先改成「每个域一句动作句」，实测还是不够（你 2026-09-18 说的「不能很好提醒模型去主动使用」），于是照着 Claude Code 与 Codex CLI 的官方注入重排成同一副骨架：`## 标题`（这条讲的是这台机器的什么）、**加粗的一句话动作**（在哪个决策点该想起它）、一行工具名 / 触发条件、一句「本份…取代本次会话中更早注入的同类…」。三条依据：动作要落在**决策点**上（Claude Code 那边做过对照：同一段正文只换标题，「Before recommending from memory」3/3，抽象主题 0/3）；工具名要写死在句子里；取代声明要写成完整句子（省得新旧两份摆在一起时模型自己猜以哪份为准）。各域的实质主张与界面标签没变，变的是结构和动作的位置。
- **场景和记忆、子智能体的引导语重写**：这两域此前只是被**陈述**，没有被**授权**。记忆那条原来写「与当前任务相关时直接采用，无关时忽略」——没给"相关"的判据（最省力的解读永远是"无关"，因为判成无关不需要任何工作）、没有优先级规则（与本机实际情况冲突时，模型默默按自己的默认假设走，而你完全不知道），而「忽略」是整句里最后一个动词。现在写「凡涉及本机路径、配置、工具或习惯，一律以它为准；无关时不必提及」。子智能体那条补上了**触发条件** —— 原来只说"委派前先在这里选人设"，没说什么样的任务该想起委派，而模型不会凭空想起一个没有触发条件的工具；现在写「自包含、能独立交代清楚的任务，先在这里选人设委派」。这两条的实质主张此后没再变过 —— 后面变的只是承载它们的外层格式（见第一条）。
- **注入正文里的重复标题删了，一处内容一个出处**：子智能体目录先去掉 `## 子智能体` 标题与「可委派给下列子智能体」那句（那条注入消息从 6 行压到 2 行）；框架定型后，`## MCP 服务器`、`## 技能` 与技能那句「没有官方 `skill` 工具」也跟着归了框架 —— 正文只排版清单。**「已清空」通知**也同步去掉了插件 id 前缀。
- **「注入实况」能看出模型到底用没用了**：每个域多一行「注入 N 次 · 调用 M 次 · 采纳 K 次」——**采纳**指"伸手用它的那一刻，这份内容正在上下文里"。此前勾了开关、正文也确实在上下文里，但模型从头到尾没伸手，界面上和「用了」长得一模一样；现在「注入了 20 次、调用 0 次」是一眼可见的结论，而不是感觉。
- **实况节头多一句观测面**（本进程观测到 N 次工具调用）：采纳次数全是 0 时，要能分清「模型真的没用」和「统计没接上」。
- **新增：人设可配「目录注入」**（`catalogDepth`）。常驻的人设目录默认**只在顶层**注入（`1`）；写 `2` 就让子会话也收到，`3` 到两层子会话。编辑器「高级选项」里有下拉。**它不限制嵌套** —— 子代理始终可以继续委派，这一条由官方决定（`dsh-tool-subagent` 默认 `maxDepth: 3`），本插件不再向官方传 `maxDepth`。子会话看不到常驻目录时，仍可用 `subagent_manager_list` 查询全部人设。
- **新增：人设子代理也能「继承本次会话」**（`subagent_manager_run` 的 `inherit`）。默认还是新起独立会话；打开 `inherit` 就换成"继承本次会话已完成对话"的机制（与官方 `subagent_fork` 同一套），任务只需写新增部分。这一档是实测逼出来的：上下文里有人设目录、也有"用 `subagent_manager_run` 执行"，模型读完 README 后照样选了官方 `subagent_fork`，因为那能继承已读内容、更省事；补齐能力比改文案更根本。顺带把**分界规则**写进工具描述与注入引导语：贴合人设的任务一律走这里，官方 `subagent` / `subagent_fork` 只在没有人设贴合、或需要后台任务时用。
- **关掉「技能」「提示词」的勾选，现在真的不注入了**：这两项在标准类预设下由宿主自己送、插件让位，所以以前取消勾选只停了插件自己 —— 宿主那份照旧进上下文。现在关掉就是关掉（宿主那份也一并停掉）。
- **人设新增「输出要求」字段（`output:`）**：一行一条硬要求（格式 / 分级 / 必标项 / 禁止项），会作为单独一节写进子代理的系统提示词。提示词写「这个角色怎么想」，这里写「产出必须长什么样」—— 只有可检验的要求才会被真的执行。编辑器里有多行框，也可以直接写进 frontmatter。顺带：`subagent_manager_run` 现在会明确要求父代理写任务时**只给目标与上下文、不规定做法**，把"怎么做"留给角色。
- **修复：「注入实况」那句说明不再被截断**（上次把标题改成不换行后它改用了省略号，状态信息被截掉半句，现在改为放不下就换行）。
- **修复：兼容页「注入实况」的标题会在窄处折成两行**（中文标题在 flex 行里的最小宽度只有一个字），现在标题不缩不换行，让位交给右侧那句带省略号的说明。
- **子代理不再收到场景记忆**：记忆只在顶层会话注入 —— 它是"父会话的现场"，不是子代理完成任务需要的事实（而且带着「一律照办」的强主张，会跟角色定义争注意力）。子代理的上下文收敛成**角色 + 任务**；要记忆它可用 `memory_manager_*` 自己取，相关事实应由父代理写进任务。MCP / 技能 / 提示词照常注入。
- **人设角色框更聚焦**：去掉了 frontmatter 的 `description`（那是**给你**选人设用的，"当用户提到审查时使用"放在子代理面前是错位信息），授权句补了半句「任务说要什么，怎么做以人设为准」——不然 `task` 会被读成人设的上级。
- **`inherit` 的说明补了限制**：只继承**已完成**的轮次。实测：父代理边扫目录边委派时，子代理其实从零开始（本轮内容继承不到），所以那种情况下任务仍要写全。
- **提示词那条注入不再「裸送」**：它此前是唯一没有框架句的域（连「取代更早的同类内容」都没有）—— 而提示词会因为**场景切换**而变化，旧那份仍留在上下文里，两份没有效力标记的正文只能让模型自己猜。现在与其余四域同款；框架定型后更进一步：**整条消息（含正文）都包进 `<system-reminder>`**（官方那两条注入行都是整条包住的），**正文里的 `</system-reminder>` 会被转义**（否则你在自己的 AGENTS.md 里写一个闭合标记，就能把框架提前关掉）。只借官方的形式，**不抄**它那句"仅供参考、不覆盖直接指令"的降级措辞。
- **提示词那条注入在界面上会写明来源文件了**：以前它是一坨原文，看不出内容来自场景提示词还是 `~/.dsh/AGENTS.md`、是这次刚载入还是换过一版；现在与官方 AGENTS.md 那条同款显示「文件 + 已载入 / 已更新」。模型侧正文后来也补了一行「来源：<文件>」（官方 `Instructions from: <path>` 同款）—— 模型知道这些规则写在哪个文件，你说"把这条记下来"时它知道该改哪份；顺带把"正文取哪份"与"界面报哪个文件"合并到一处解析，两边不会各说各话。
- **五个管理工具的描述会指回注入块**（「同一份清单每轮也注入在上下文里，见那条 system-reminder」）：目录和工具互相指路，模型更容易在对的时刻想起来用。另外修了 `subagent_manager_run` 描述里一句悬空的「personas below」（人设清单不在工具下面，在上下文里）。
- **人设目录的过滤判据最终定在「目录该不该注入到这么深的会话」**：中途曾用过"还有没有委派预算"，那仍是"能不能委派"的思路 —— 而委派根本不受本插件限制（官方默认就能嵌套）。现在判据只回答目录可见性（`深度 < catalogDepth`），目录过滤、域声明、实况状态三处共用。实况里那档灰色状态随之改称「不在本会话注入」。
- **「注入实况」的两档状态改名，行也终于对齐了**：绿色那档从「在上下文中」改成「**已注入**」（同一个面板里「官方注入」已经用了"注入"这个动词，说法统一后不必再分辨"上下文"指的是谁的）；没有正文可展开的行（状态是「已清空」那种）此前没有展开箭头，域名比别行左移一个字宽、整列参差不齐，现在留了等宽空白占位 —— 但**不给不可展开的行画箭头**，画了就是假装它能点。
- **修复：子会话里调委派工具不再被本插件拦下**：此前我们向官方传 `maxDepth: 1`，子会话再委派会撞 `SubagentDepthError`，本插件又加了一道守卫提前拦下。但官方默认是 `3` —— 子代理本来就能嵌套，那道守卫只是让我们的工具比官方严（同一个子会话里官方工具能委派、我们的不能），而且你真想禁止嵌套也禁止不了。现在不再传 `maxDepth`，守卫一并拆掉；`subagent_manager_list` 也不再按深度过滤（它此前会把可用人设藏起来，而目录不注入时它是唯一的信息源）。
- **修复：MCP 状态不再把「连不上」说成「可用」**。判可用的那个工具数此前混了三处来源，其中「已知工具」缓存（上次连上时见到的工具名）在服务器坏掉之后**依然算数** —— 于是只要它曾经成功连上过，坏掉之后状态栏还是绿色「已运行」，注入给模型的清单也照旧说它可用，模型照着去调那个工具、而它根本没注册。现在工具数按来源拆开，状态栏、页面总数与注入清单一律只认**当前真实注册**的那个数。
- **新增：注入清单里会如实标出「当前未连上」**。已启用、当前没有工具、但曾经连上过的 server 会列成 `- **tavily**（当前未连上；上次连上时 5 个工具）` —— 这样你问它"帮我搜一下"时，它会说"tavily 没连上，检查一下"，而不是"本机没有这个工具"。**从未连上过的不列**（一直没成功过，不该反复打扰），你主动关掉的和工具全被停用的也不列。
- **子代理看到的人设不再是裸正文，而是一段带框的角色定义**：此前人设直接拼进系统提示词，紧贴那句 `You are an AI agent powered by DeepSeek Harness.`，既没标题也没归属——模型读成身份句的续写，你写的「必须…」只是背景信息。现在人设带 `# 角色：名` 标题、一行授权（「由调用方指定，与你的默认倾向冲突时以它为准」）和一句边界（决定**怎么做**，不改变**能做什么**），正文用 `## 角色定义` 围起来；框的语言跟随**人设整体**（名字 + 描述 + 正文）。**人设文件本身一个字都不用改。**
- **修复：子代理返回的结果里混着它的思考**。官方的子代理结果是一串内容块，其中「思考」块和「正文」块长得一模一样（都带文本字段），插件摊平时少判了一步类型，于是把思考当成了正文——返回结果的开头多出「我做了 1、2、3」这类自我校验，正文被顶到后面；只有思考时就整段都是思考。现在按官方的口径只取正文块。**本机 298 条子代理结果里 294 条命中**。
- **修复：「子代理没有产出正文」不再一律报成「无输出」**。上面那批里有 83 条修完后会变成空的，而「没干活」和「干了活但没写出正文」是两件事，报成同一句会让人误判。现在按收尾原因分开说（撞 token 上限 / 出错 / 被中止各有各的说明与对策）——因为实测发现这批里**没有一条是正常结束的**，所以对策是「把任务拆小或先看诊断」，而不是原样再发一次。
- **修复：人设正文里写 `{{…}}` 会让子代理启动失败**（宿主把它当未注册的提示词变量直接抛错）。现在这类花括号会被拆开，模型看到的字面量不变。
- **修复：在场景里关掉一个技能目录（或一台 MCP 服务器），退出后那一行不回**。表现是「A 目录」和它下面的技能一并在关闭状态——退出时的还原名单此前只记「进场景那一刻被档案改动过」的行，而你在场景页面上手动关掉的行刚好不在其中（技能这一域更彻底：目录关着时，它下面技能的开都会被忽略）。现在进场景时全量记下每一行的原状态，退出时逐行比对，只把你真改过的那几行还原回去，其余一行都不碰。
- **MCP 列表改成「全局在上、应用级在下」，两边都按服务器名排**。此前应用级在前、组内按补丁文件里的书写顺序，找一台全局服务器要翻过整张应用级表。顺序现在由服务端统一给出，MCP 页、场景档案的服务器勾选器、模型看到的清单三处一致。
- **修复：技能页页头的「全选」不再被挤到第二行**。技能页有 7 颗页头按钮，是全站最挤的一条 —— 常规档（13px 字号）整行要 560px 宽，面板一窄，最后一颗「全选」就折到第二行（你 2026-09-18 截图指出）。现在**面板窄（≤600px）时这一行动作自动收一档**：字号 12px、内边距 8px、间距 6px，整行降到 486px 就放得下；面板宽时保持原样。点「全选」变「取消全选」不跳宽、整行不重排这条约束照旧（按钮宽度按较宽的那份文案预占）。再窄（< 486px）仍按原来的方式折行。

## 0.9.1 - 2026-09-17

- **兼容页新增「注入实况」**：直接看最近活跃会话里模型**实际收到**的五域文本，并分清「在上下文中 / 未投递 / 官方注入 / 已关闭」——勾了开关却没送到时一眼可见。
- **场景里也能直接开关了**（未锁定时）：MCP、技能、子智能体、提示词照常改——**改动会同步写进这个场景的档案**，当下生效、下次进这个场景也照样生效，退出仍按进场景前的状态还原；只有**锁定**才冻结。
- **「全选」统一成二合一**：所有全选按钮都是「全选」↔ 点完变「取消全选」，不再并列两个；技能管理页、记忆管理页、记忆的每个场景卡片补上了缺的批量开关。
- **技能管理页每个来源（目录）卡片也有批量开关**，点「全选」或卡片上的来源开关都会顺带把这张卡片展开——批量结果就在下面，不然点完只剩按钮改了字。
- **人设也严格「退出即还原」**：场景里手动打开的人设，退出时会回到进场景前的状态（场景中新建的不受影响）。
- **bundle 记忆会显示带了几个附件**：记忆行上多一颗「N 个附件」标签（一个都没有的也显示，灰色），鼠标停上去能看到总量与文件名，点一下直接打开编辑弹窗并跳到附件区。
- **技能目录卡片上的「移除来源」改成一个垃圾桶图标**：它是低频的破坏性操作，却和「全选」并排、还带红框，四个字一挡上去整行看着就不协调；鼠标停上去会说明后果，点下去照旧弹确认框。
- **按钮位置**：MCP 页的「全部启用 / 全部停用」移到页头动作栏；会话页的「全选」移到「导出会话」旁。
- **修复：退出场景失败、卡在场景里**（报错里出现「技能来源 project-dsh:… 启用失败」）：项目级来源的解析依赖那个工作区还在活动会话里，退出时早关了 → 报错中断，于是再也退不出来；现在按 key 前缀解析，真恢复不了的只跳过并警告。
- **修复：场景里打开技能，档案不跟着变**：开关的参数里没有「开 / 关」（方向写在操作名里），同步逻辑却去读那个不存在的字段，于是所有「打开」都被当成「关闭」、开关白点；现在按操作名判方向，档案没写成时页面也会如实提示。
