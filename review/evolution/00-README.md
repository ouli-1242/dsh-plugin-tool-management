# 主动记忆与自进化：设计文档集（v0.3）

> 对象：本仓库 `dsh-plugin-tool-management` 0.22.5。状态：设计定稿候选，**源码一行未改**。
>
> v0.2 是一份 1417 行的单文件（已归档到 `archive/v0.2-single-file.md`）。v0.3 按"能不能照着写代码"的标准拆成 9 份，每份只回答一类问题，互相之间用相对路径引用。

## 0. 这一版解决了什么

v0.2 把"层"（global / workspace / scene / session）当成了记忆的归属，把"自动记忆"当成 `origin=auto` 的一个桶。这留下三个没回答的问题：

1. **"在哪学"和"存到哪"是不是同一件事？** v0.2 混着用，导致"我这个会话开着自进化，但学到的都是工作区事实"这种诉求无法表达。
2. **能不能只给一个会话或一个工作区开？** v0.2 只有一个全局开关，虽然提了"层级"，但没有继承链。
3. **记忆多到几百条之后，每会话还要读全文吗？** v0.2 只说了预算，没说索引。

v0.3 的三个结构性改动：

| 改动 | 内容 | 落在 |
| --- | --- | --- |
| 三轴拆分 | `layer`（生效层）/ `origin`（来源）/ `learnScope`（学习域）互相正交，可交叉组合 | `01-model.md` |
| 三级开关 | 全局 → 工作区 → 会话，逐字段继承，下层可覆盖上层的"关" | `01-model.md` §3 |
| 一条一文件 + catalog | 存储仍是一条一文件；注入只读派生索引，不读正文 | `02-storage.md` |

## 1. 一页纸结论

```text
一个总开关（默认关），但有三级：全局 / 工作区 / 会话，就近覆盖
三个正交的轴：layer（存哪=哪可见）× origin（谁写的）× learnScope（在哪学）
一条记忆一个 md 文件（复用现有扫描/索引/回收站），另建 catalog 供注入热路径读取
四层目录：global / <scene> / _ws/<hash> / _session/<sid>，目录即层
一个新工具 memory_manager_learn（自动写），save 保持"用户指令"原契约
一个 forget（删单条+墓碑）、一个 organize（只出草案），结构性操作不给模型
一条后台管线：turn/end 入 outbox → 复习 → 九道门 → 路由 → 落盘
一个整理任务 dream：输入不动，输出草案，可审阅可回滚
一条晋升阶梯：episode → note → memory → core → playbook → skill（技能必须人工确认）
一个硬边界：只写本插件自己的记忆/技能文件，不碰宿主工具、预设、MCP、插件代码
```

## 2. 五个问题去哪找答案

| 你的问题 | 章节 | 一句话答案 |
| --- | --- | --- |
| agent 怎么管理这些记忆？ | `05-tools.md` | 模型只有"读 + 追加 + 忘单条 + 提议整理"；合并/换层/批量删只走 dream 草案 + 你确认 |
| 能不能交叉组合？比如生效层是会话、自进化的记忆是工作区的 | `01-model.md` §2 | 能，但要拆成两句：`learnScope=session`（在哪学）+ `writeTarget=workspace`（存哪）。**存哪就是哪可见**，不存在"存在工作区但只在会话生效" |
| 记忆越来越多怎么办？ | `04-governance.md` | 四道闸：写入配额、注入分级（常驻/排序/按需/归档）、时间衰减、dream 合并；catalog 让读取成本与条数脱钩 |
| 每条记忆一个 md 还是合并？ | `02-storage.md` §1 | 一条一文件。合并省的是读取，丢的是单条回滚和并发安全；读取用 catalog 解决，不用合并解决 |
| 能不能只给这个对话/工作区开？ | `01-model.md` §3 | 能。全局关 + 会话开、全局关 + 工作区开，都是合法组合；下层显式设置覆盖上层 |

## 5. 与 v0.2 的差异清单（评审用）

| # | v0.2 | v0.3 | 为什么改 |
| --- | --- | --- | --- |
| 1 | `_auto` 单一自动桶 | 自动记忆按层分散在四个目录，用 `origin=auto` 标识 | 用户要"会话学、工作区存"，单桶表达不了 |
| 2 | 只有全局开关 | 全局 / 工作区 / 会话三级继承 | 用户要"只给这个对话开" |
| 3 | `scope` 字段三值 | `layer` + `learnScope` + `writeTarget` 三字段 | 一个字段承担不了三种语义 |
| 4 | 注入时扫目录读正文 | 注入只读 `catalog.json`，正文懒加载 | 300 条时全读约 100–300ms，catalog 约 10ms |
| 5 | 工具只有 learn 新增 | 新增 learn / forget / organize；promote 不给模型 | 用户说"忘掉"时需要有工具接 |
| 6 | 会话层只自动写 | 会话层可被 `save` 显式指定（需确认） | 用户说"这次别动 migrations，记住"是合理诉求 |
| 7 | 场景层可自动写 | 场景层仍可写，但**不是默认落点**，要明说 | 场景默认不启用，写进去就等于丢 |
| 8 | 文档单文件 1417 行 | 9 份，按问题分 | 你说"计划可以分多个文件" |

## 6. 仍然不变的七条（v0.2 的核心判断，继续成立）

1. 不另起炉灶：内容进现有 `memories/`，注入走现有 `memory-manager-catalog` 域，UI 在「记忆」页。
2. 模型只提议，代码写：证据、去重、冲突、配额全部在代码里判，不信任模型自报。
3. 禁止整段重写：只做 delta + 计数器（ACE 实测过 context collapse：18,282 token 压到 122 token，准确率掉 9.6 分）。
4. 会话内注入稳定：自动块自己缓存，不跟着每次学习重发。
5. 两层权威声明：用户写的和自动学的必须分开声明，否则模型把三个月前的笔记当命令。
6. 可回滚：任何结构性变更都有 reason、有 backup、有 undo。
7. 全本地：`$DSH_HOME`，不联网，不上传；复习用宿主模型，不额外发请求。
